# المراقبة واستعادة إعدادات الخادم

## المنفّذ على الحساب الخارجي

بتاريخ ٢٧ نوفمبر ٢٠٢٦ أضيفت مراقبتان في UptimeRobot كل خمس دقائق:

- `https://www.tevoniq.com/ar`، المعرّف `804827683`.
- `https://www.tevoniq.com/health`، المعرّف `804827687`.

ظهرتا بحالة Up، وضبط البريد إلى `ecobaxi@gmail.com`. شُغّل إرسال تنبيه تجريبي؛ استلامه يحتاج التحقق من صندوق البريد. هذا مستقل عن كهرباء وإنترنت المنزل. `/health` يفحص الويب فقط؛ لا يثبت وحده اتصال PostgreSQL. لم نوقف الموقع عمدًا لاختبار الانقطاع.

## تجهيز فحص الخادم المحلي

`install-monitor.sh` ينسخ إعداد المرسل ومفتاح Resend الحاليين من حاوية API إلى `/etc/tevoniq-monitor/config.json` بصلاحية root و600 دون طباعتهما. لا ينشئ مفاتيح بديلة، ولا يتطلب إعادة بناء التطبيق. الإرسال من Python على المضيف، فلا يعتمد بعد التثبيت على تشغيل API أو Docker.

الفحص كل ١٥ دقيقة يشمل:

- امتلاء القرص بنسبة ٨٥٪ أو بقاء أقل من ١٠ GiB.
- آخر نتيجة لخدمتي النسخ المحلي والخارجي، وعدم اكتمال تشغيل خلال ٤٢ ساعة.
- توقف مؤقتَي النسخ، وعدم سلامة الحاويات الثلاث.

يرسل أول مشكلة، ويكرر الحالة نفسها بعد ست ساعات، ويرسل عند التعافي. تغير مجموعة المشكلات يرسل تنبيهًا جديدًا. فشل إرسال البريد لا يسجل التنبيه كمرسل كي يُعاد في الجولة التالية. لا تتضمن الرسائل أسرارًا أو سجلات التطبيق أو محتوى القاعدة. قبول Resend للطلب لا يثبت وصوله لصندوق الوارد. انقطاع الإنترنت يمنع البريد المحلي؛ تغطيه المراقبة الخارجية. تعطل برنامج المراقبة نفسه يحتاج مراجعة سجله؛ ليس لدينا تنبيه خارجي لنبضه حاليًا.

## النسخة المشفرة من إعدادات التشغيل

أضيف `backup-config.sh` كخطوة `ExecStartPost` للنسخ الخارجي. يحتفظ بقائمة محددة من ملفات البيئة وCompose وDockerfile وأدوات التشغيل ووحدات systemd وإعداد rclone وإعدادات المراقبة والجدار الناري وسلوك الغطاء إن وجدت. لا ينسخ بيانات وسائط المستخدمين، ولا يحتوي مفتاح فك تشفير Restic نفسه. المفتاح محفوظ بصورة مستقلة على الماك.

هذه الملفات **تحتوي أسرارًا**، لكن يُرفع أرشيفها داخل مستودع Restic المشفر نفسه، بوسم منفصل `tevoniq-config`. تُفحص النسخة بتنزيلها ومقارنتها بالأصل قبل تطبيق سياسة ١٤ يومية و٨ أسبوعية و٦ شهرية لهذا الوسم فقط. تبقى نسخة PostgreSQL بوسمها المستقل. فشل نسخة الإعدادات يجعل خدمة النسخ الخارجي تفشل ويظهر في الفحص الدوري.

## التثبيت على Ubuntu

من الماك:

```bash
ssh -t tevoniq@192.168.1.133 '
  set -e
  cd ~/apps/tevoniq
  git pull --ff-only
  sudo bash scripts/home/install-monitor.sh
  sudo bash scripts/home/install-offsite.sh
  sudo systemctl start tevoniq-offsite.service
  sudo systemctl show tevoniq-offsite.service -p Result -p ExecMainStatus
  sudo journalctl -u tevoniq-offsite.service -n 12 --no-pager
'
```

لا تستخدم `--init`؛ المستودع موجود بالفعل. إرسال البريد التجريبي يجري أثناء التثبيت. انتظر نجاح النسخة الجديدة قبل اعتبار إعدادات الخادم محفوظة في السحابة. لا تنفذ استخراجًا فوق ملفات النظام الحية.

مثال استرجاع أرشيف الإعدادات إلى ملف root خاص، دون تطبيق محتواه أو طباعته:

```bash
sudo bash -c 'set -a; . /etc/tevoniq-backup/offsite.env; set +a; umask 077; restic dump --host tevoniq-home --tag tevoniq-config latest /server-config.tar > /root/tevoniq-server-config.tar'
```

قد تحتاج نقل خدمة cloudflared أو إعادة تسجيلها عند تغيير الجهاز؛ حفظ ملف الوحدة ليس ضمانًا لوجود أي ملفات credentials خارج القائمة. لا تشمل النسخة صورة نظام كاملة، أو إعدادات الراوتر، أو ملفات الوسائط القديمة في volume التطوير. افحص volume الإعلام القديم بصورة مستقلة قبل إزالة أي خدمة قديمة.

## ما لم يكتمل بعد

- التشغيل الفعلي لهذه الإضافة على Ubuntu واستلام بريد الاختبار.
- مراجعة بيانات Neon بعد تجدد حصة التشغيل، ثم اتخاذ قرار إلغاء Render وNeon. لا تحذفهما الآن.
- صلاحيات تنزيلات Pesto واختبار النماذج والبريد بالكامل موثقة بحسب التحقق الفعلي، وليست مفترضة.

مرجع واجهة البريد: https://resend.com/docs/api-reference/emails/send-email

## تحقق النقل بتاريخ ٢٧ نوفمبر ٢٠٢٦

- صفحات ar وen وar/start وar/contact وar/insights/resources وar/insights والإدارة وhealth وrobots.txt وsitemap.xml وصفحتي تأكيد وإلغاء النشرة أعادت HTTP 200. هذا فحص توفر فقط، وليس إثبات إرسال نموذج أو تأكيد اشتراك فعلي.
- حُوّلت مشاركة ملف Android ومجلده `PestoLite APK 1.3.4`، وملف Windows ومجلده `PestoLite 1.3.4 Windows` من Editor إلى Viewer بموافقة المالك. أُعيد فتح نافذة المشاركة لكل ملف وتحقق ظهور Viewer وبقاء Anyone with the link.
- تعرض لوحة Neon استنفاد 100 CU-hrs وتجدد الحصة في ١ ديسمبر ٢٠٢٦ 00:00 UTC، أي 03:00 بتوقيت إسطنبول. لم تُفحص صفوف قاعدة Neon، ولم تُحذف أي خدمة قديمة.
- اختبارات محلية: ٦ لاختيارات التنبيه والتعافي والتأخر وفشل البريد، و٧ قائمة لنسخ القاعدة والاحتفاظ وإعدادات المنزل. لم تُشغّل systemd أو Docker في بيئة الماك؛ اعتماد التفعيل على نتيجة أمر Ubuntu.
