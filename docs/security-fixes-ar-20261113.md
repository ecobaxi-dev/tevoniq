## إعدادات النشر المطلوبة

لا تضع أي مفتاح سري في Git أو المحادثة أو متغير NEXT_PUBLIC_.

1. `TURNSTILE_MODE=turnstile` ومفاتيح `TURNSTILE_SITE_KEY` و`TURNSTILE_SECRET_KEY` الفعلية، و`TURNSTILE_HOSTNAMES` التي تشمل اسم نطاق SITE_URL المستخدم فعلًا.
2. `LEAD_PROXY_SECRET` عشوائي بطول 32 حرفًا على الأقل ومتماثل في Web وAPI. في إعداد Render الموحّد يولَّد مرة واحدة ويورثه الخادمان.
3. `LEAD_CLIENT_IP_HEADER`: ترويسة يكتبها ingress الموثوق بنفسه. لا يكفي اختيار ترويسة يقدر الزائر على تعيينها.
4. إذا كانت الترويسة `x-forwarded-for`، يلزم `LEAD_TRUSTED_PROXY_HOPS` بعد التحقق من عدد القفزات الموثوقة فعلًا؛ يتم الاختيار من يمين السلسلة. لا توجد قيمة تخمينية افتراضية. لا تفعّل trust proxy بصورة عامة.
5. `EMAIL_TRANSPORT=resend` مع EMAIL_FROM ومفتاح المزود، أو smtp بإعداداته الصحيحة. إتاحة المزود هنا تعني أنه مضبوط برمجيًا، وليس إثباتًا لوصول البريد.
6. `SITE_URL` و`CORS_ORIGIN` أصل HTTPS متطابق. استخدم نطاق الإنتاج المعتمد، مع www أو بدونه وفق إعداد الموقع.
7. `ENFORCE_RELEASE_SECURITY=true` في مخطط Render الجديد. يبدأ فحص الإعداد قبل migrations أو فتح منافذ الخدمة، ويوقف الإصدار غير المكتمل برسائل أسماء الحقول دون قيمها.

لا تفعّل أي متغير لتسجيل/تحميل بيستو ضمن هذه المهمة؛ بوابات جاهزيته القائمة مستقلة.

## ترتيب النشر والتحقق

- شغّل الاختبارات وبناء الحزم على Node 24. راجع التغييرات الحالية ثم ثبّتها في Git عندما ننتقل إلى النشر.
- اضبط مفاتيح الحسابات والترويسة الموثوقة أولًا، ثم انشر Web وAPI والحزم المشتركة مع lockfile الجديد. لا يلزم حذف بيانات أو seed أو reset.
- تحقق من GET للمسارين `/ar/start` و`/en/start` على نطاق الإنتاج، ومن استجابات API والصور.
- اختبر استقلال حصتي زائرين عبر ingress الحقيقي، ورفض الترويسات المزورة. الاختبار العددي الموجود في هذه المهمة محلي فقط.
- اختبر طلب تواصل واحدًا مصرحًا به ووصوله للإدارة والبريد، ثم اشتراك النشرة/التأكيد/الإلغاء.
- اختبر Turnstile برمز صحيح وآخر غير صالح/منتهي/لنطاق مختلف. تظل مفاتيح الاختبار محصورة في الاختبارات المحلية.
- تحقق من رفض التتبع عند الرفض، ومن تحويل واحد عند استلام الطلب بنجاح، عبر Google/Meta بحساباتهما الفعلية. لا يُعد وجود أحداث JavaScript إثباتًا لوصولها للحساب.

## حزمة المصدر المجهزة

تُنتج بالأمر `python scripts/package-release.py` في `artifacts/release/tevoniq-source.tar.gz` ومعها SHA256SUMS وmanifest.json. تحتوي المصدر والأصول وملفات القفل والتجهيز، وتستبعد ملفات البيئة الفعلية والمفاتيح وقواعد البيانات المحلية وnode_modules ومخرجات البناء. هذه حزمة مصدر تحتاج البناء على Node 24، وليست نشرًا على الإنتاج.

**المتبقي التنفيذي المتفق على تأجيله:** إدخال مفاتيح Turnstile وإعداد ingress والبريد في Render/Cloudflare، ثم نشر الحزمة والتحقق من رابط الإعلان والبريد والتحويلات الفعلية. لذلك يبقى SEC-02 وREL-01 مفتوحين تشغيليًا رغم اكتمال التجهيز البرمجي، وتحتاج بقية تغييرات الكود النشر كي تسري على الموقع العام.
