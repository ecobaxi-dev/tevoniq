## 1. تعريف المشروع وقراراته

TEVONIQ موقع شركة ومنصة محتوى وخدمات رقمية تستهدف المنشآت الصغيرة والمتوسطة في السوق العربي. المقر الرئيسي المعتمد من المالك: إسطنبول، تركيا. المؤسس خريج هندسة الحاسب من جامعة أريل، ويعمل حاليًا بنفسه بمساعدة الأدوات الحديثة والذكاء الاصطناعي.

نخاطب الجمهور باسم الشركة. لا نختلق عملاء أو موظفين أو اعتمادات أو شراكات أو نتائج تنفيذ. الأمثلة والنماذج ليست أعمال عملاء. العربية المدخل الأساسي؛ التطوير والمحتوى الجديد بالعربية والإنجليزية فقط، مع الحفاظ على التركية الموجودة. اختيار اللغة الصريح وإعدادات اللغات المفعّلة يظلان محترمين.

المنتجان المعروضان: Pesto وAdvocas «المحامون». Pesto مملوك للمؤسس. لا تفعّل التحميل أو التسجيل أو التجارب أو الترخيص لمجرد مرور موعد تقديري؛ يلزم تحقق الجاهزية وإعدادات الخدمة الفعلية.

المصادر الحاكمة: [AGENTS.md](../AGENTS.md)، [قرارات الاتجاه](project-direction-ar.md)، [الجرد](sme-site-inventory-ar.md). الجرد توصيات وليس إذنًا بحذف محتواه كله.

## 3. النطاق وDNS

القيم التالية قُرئت من DNS العام يوم إعداد الملف، ويجب إعادة التحقق قبل أي تغيير:

| السجل                     | القيمة                                                     |
| ------------------------- | ---------------------------------------------------------- |
| NS                        | `dns1.registrar-servers.com` و`dns2.registrar-servers.com` |
| CNAME لـ`www.tevoniq.com` | `tevoniq-preview.onrender.com`                             |
| A للنطاق `tevoniq.com`    | `216.24.57.1`                                              |
| تحقق HTTP                 | `/ar` أعاد 200 عبر HTTPS عند الفحص                         |

حساب مسجّل النطاق وبيانات دخوله وتاريخ التجديد لم تكن متاحة. لا يُستنتج اسم المالك أو مسجّل النطاق من أسماء NS وحدها. راجع حساب النطاق لإدارة التجديد وDNS، وراجع Custom Domains داخل Render عند تغيير الربط. لا تغيّر سجلات البريد أو التحقق من النطاق أثناء نقل الموقع دون جردها.

## 4. الاستضافة والنشر الحاليان

إعداد `render.yaml` الملتزم بالمستودع:

- خدمة Node واحدة باسم `tevoniq-preview`، خطة `free`، منطقة `frankfurt`.
- Node 24، و`NODE_ENV=production`.
- البناء: `npm ci --include=dev && node scripts/render/build.mjs`.
- التشغيل: `node scripts/render/start.mjs`.
- Health Check: `/health`.
- `autoDeployTrigger: off`: رفع Git وحده لا يثبت نشر النسخة؛ راجع إعداد Render الفعلي ونفّذ Manual Deploy عند الحاجة.
- واجهة Next.js على منفذ Render العام، افتراضيًا 10000. API داخل الخدمة على `127.0.0.1:4000/api/v1`، ولا تُعرّضه للعامة.
- `SITE_URL=https://www.tevoniq.com`، و`CORS_ORIGIN` يطابقه حرفيًا. لا تستخدم apex دون www في إعداد الأصل لهذا النشر.
- سكربت البيئة يحدد API الداخلي ويربطه بالـloopback. سكربت البدء يطبق migrations أولًا، ثم bootstrap الآمن، ويطلق API وبعد جاهزيته يطلق الويب.
- `MEDIA_STORAGE=disabled` و`TURNSTILE_MODE=disabled` هما إعدادا Blueprint، وليس إثباتًا للوضع الفعلي في Environment الآن.
- تبقى قاعدة Render القديمة `tevoniq-preview-db` في Blueprint للرجوع. لا تحذفها تلقائيًا ولا تفترض أن بياناتها الحالية هي المستخدمة.

خطة الحساب والفوترة والتشغيل الفعلي ونسخة النشر الأخيرة تُراجع في لوحة Render؛ لم يُتح الوصول إلى إعداداتها الخاصة. استضافة free المذكورة في الإعداد لا تثبت الترقية أو التغيير اللاحق في الحساب.

### نشر تحديث

1. اعمل على فرع تطوير، وراجع تغييرات المحتوى والخدمات المتقاعدة.
2. شغّل الفحوص الملائمة، واحفظ نقطة رجوع للكود.
3. ارفع التحديث المعتمد إلى `main`.
4. في Render اختر الخدمة الصحيحة وانشر التحديث الصحيح يدويًا عند تعطيل النشر الآلي.
5. راقب بناء الحزم وAPI والويب، وتطبيق migrations، ثم readiness وبدء الويب.
6. اختبر الموقع والإدارة والنماذج والملفات والمساعد وسياسة النشر واللغات. لا ترسل نماذج إنتاج آلية كاختبار دون غرض واضح ومتابعة تنظيفها.
7. إذا تغيّرت API أو حزمها أو عقد البيانات، انشر الويب وAPI معًا؛ في خدمة Render المجمعة يشملهما البناء نفسه. تغييرات CSS فقط لا تحتاج ترحيل بيانات.

## 9. التطوير المحلي

المطلوب Node 24 وnpm 11. استخدم `.nvmrc`. قبل البرمجة في الويب اقرأ `apps/web/AGENTS.md` ودليل Next المحلي داخل `node_modules/next/dist/docs`؛ المشروع على Next 16 وله فروق عن الإصدارات السابقة.

```sh
git clone https://github.com/ecobaxi-dev/tevoniq.git
cd tevoniq
npm ci
npm run env:setup
npm run infra:up
```

`env:setup` لا يستبدل ملفًا موجودًا. تأكد من توجيه قاعدة البيانات إلى **تطوير معزول** قبل بقية الأوامر، ولا تستخدم اتصال الهدف الإنتاجي المحفوظ تلقائيًا.

```sh
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

`db:migrate` و`db:seed` للتطوير؛ seed ليس لتعبئة الإنتاج. المنافذ المحلية: الويب 3000، API 4000، PostgreSQL 5432 افتراضيًا. `npm run dev:neon` يعطي أولوية لاتصال Neon في الجذر؛ لا تستخدمه قبل تصحيح الاتصال القديم وتحديد فرع تطوير مناسب.

## 10. النشر والمحتوى وSEO والحماية

- `packages/types/src/retired-catalog.ts` هو المرجع الملزم للخدمات المتقاعدة، في كل اللغات والتنقل والبحث وSEO. لا تعِد عرضها من CMS قديم أو حزمة استيراد.
- API وBFF يتحققان من النشر والصلاحيات؛ لا تُرجع محتوى تجريبيًا عند خطأ مصدر المحتوى. لا تغيّر 404 إلى صفحة منشورة وهمية.
- الصور العامة في `apps/web/public/brand`؛ المرفقات الخاصة وCV ليست ملفات عامة. الإنتاج يتطلب تخزينًا دائمًا وفحصًا عند تشغيل الرفع.
- HTML يحمل CSP nonce ولا يُخزّن في cache عام. الأصول الثابتة تستخدم سياساتها. بيانات CMS العامة لها cache بعلامة تُبطل عند الحفظ عبر CMS.
- واجهات API لا تُفهرس ولا تُخزّن ردودها الشخصية. كوكي CMS HttpOnly وSecure مع HTTPS وSameSite=Strict؛ الحماية لا تعتمد على إخفاء `/admin`.
- عناوين ووصف SEO والهوية واللغات قابلة لإعدادات CMS. الموارد AR/EN تستخدم `/insights/resources/`، والتركية تحتفظ بمسارها القديم. سجلات noindex وcanonical الصريح تُحترم.
- المراجعة الأمنية بتاريخ 1 نوفمبر أزالت التنبيهات المعروفة لحزم الإنتاج وقتها؛ بقيت تنبيهات متوسطة في أدوات التطوير. هذه لقطة تاريخية، فأعد الفحص عند تحديث الاعتماديات.

راجع [المراجعة الأمنية وSEO](site-security-seo-audit-ar-20261101.md)، [توثيق SEO](seo.md)، [الحماية](../SECURITY.md)، [النشر](../DEPLOYMENT.md)، [المعمارية](../ARCHITECTURE.md).

## 11. النسخ الاحتياطية والرجوع

المستودع ليس نسخة احتياطية لقاعدة البيانات أو الوسائط أو الأسرار. وُجدت نسخ نقل خاصة مؤرخة 23 أكتوبر 2026 داخل `.data/neon`؛ آخر نسختين غير الفارغتين حجمهما 236198 بايت لكل منهما. توجد أيضًا محاولتان فارغتان بحجم صفر، فلا تختارهما للاستعادة. لا تعتبر أي نسخة قديمة بديلًا لنسخة إنتاج حديثة.

قبل تعديل بيانات مهم: نسخة قاعدة حديثة عبر اتصال مباشر، ونسخة وسائط ومفاتيح وإعدادات منفصلة، ثم اختبار استعادة في قاعدة معزولة. لا تشغّل `pg_restore --clean` على قاعدة حيّة من هذا الدليل. `editorial-transfer` لا يشمل المستخدمين والأسرار والطلبات الخاصة؛ ليس نسخة استعادة كاملة.

لرجوع الكود، توجد tags من نمط `checkpoint/*`. لا تستخدم `reset --hard` أو force push على `main` كإجراء عادي. اختر commit سابقًا في Render أو طبّق revert مراجعًا ثم انشر. رجوع التطبيق لا يعني جواز عكس migration تلقائيًا.

## 13. معلومات لم تتوفر ومواضع استكمالها

- كلمة مرور CMS الحالية المؤكدة: حساب المالك/مدير كلمات المرور أو إعادة تعيين مصرح بها. القيمة المحلية المحفوظة غير مؤكدة.
- كلمات مرور المنصات وMFA ورموز الاسترداد: لدى المالك، وليست في المستودع.
- أسرار Render الفعلية: Environment في الخدمة الصحيحة؛ لا تنقلها إلى ملف Git.
- التوكن الفعلي للمساعد: سر في Render/Cloudflare؛ تجديده إجراء مستقل، ولا يُنشأ من مجرد تغيير اسم النموذج.
- بيانات البريد والتخزين والفاحص المفعّل: راجع البيئة ولوحات المزوّدين.
- هوية مالك تسجيل النطاق والتجديد والفوترة وحدود الخطط وتاريخ الاستعادة: راجع الحسابات الإدارية.
- مشروع/ملكية Google Search Console: لم تُتح للتحقق. إرسال sitemap لا يضمن الفهرسة أو ترتيبًا معينًا.
