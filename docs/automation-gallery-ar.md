# معرض الأتمتة والربط

توسعة البطاقة الثالثة إلى `/ar/automation-demos` و`/en/automation-demos`، مع تفاصيل لكل نموذج ومحاكاة مستقلة تحت `/previews/[locale]/automation/[slug]`.

| النموذج               | المعرّف                 | ما تُظهره التجربة                                                          |
| --------------------- | ----------------------- | -------------------------------------------------------------------------- |
| الاستفسارات والمتابعة | `lead-capture`          | فحص بيانات الاستفسار، تجهيز سجل متابعة ومسودة رد بحسب تفضيل التواصل        |
| الطلب والمخزون        | `order-sync`            | فحص الكمية والرصيد، حد مراجعة بالقيمة، موافقة وتجهيز التنفيذ               |
| تذكير المواعيد        | `appointment-reminders` | تاريخ مرجعي، تجاوز الماضي أو عدم التواصل، حساب التذكير قبل الموعد بيوم     |
| متابعة الفواتير       | `invoice-follow-up`     | تجاوز المدفوع وغير المستحق، مراجعة التواصل والقيمة والموافقة، مسودة متابعة |
| تنبيه نقص المخزون     | `stock-alerts`          | حد تنبيه، تجاوز الرصيد الكافي، موافقة ومقترح طلب مراجعة توريد              |
| ملخص الطلبات          | `daily-summary`         | فحص السجلات والتكرار والقيم وتجميع العدد والمجموع والمتوسط                 |

## النطاق

- جميع البيانات والهويات والمسارات توضيحية أصلية، وليست أنظمة عملاء أو اتصالات فعلية ببرامجهم.
- لا تُرسل المحاكاة بريدًا أو رسائل، ولا تُنشئ حجوزات أو فواتير أو أوامر شراء ولا تعدّل أرصدة خارجية. المخرجات مسودات محلية مؤقتة.
- المدخلات قابلة للتعديل، مع تشغيل مرئي للخطوات وتجاوز المشروط أو انتظار الموافقة أو محاكاة فشل الوجهة وإعادة المحاولة.
- رقم الحدث يمنع إنتاج نتيجة إضافية للبيانات نفسها. إعادة استخدامه لبيانات مختلفة تعطي تعارضًا؛ تغيير الموافقة وحده لا يغير محتوى الحدث.
- لا تُسجل نتيجة مكتملة عند الفشل أو انتظار الموافقة؛ تسمح إعادة المحاولة بالرقم نفسه بعد معالجة السبب. النتائج المكتملة أو المتجاوزة تُحفظ في ذاكرة الصفحة لمنع التكرار حتى إعادة التحميل أو تأكيد إعادة التجربة.
- ملخص الطلبات يقبل حتى 20 سطرًا بصيغة `ID,amount` ويمنع أرقام الطلبات المكررة والقيم غير الصالحة. القيم مالية توضيحية وليست تقريرًا محاسبيًا أو عملية تحصيل.
- التاريخ المرجعي في البيانات يختاره الزائر؛ لا توجد جدولة زمنية حقيقية أو مهمة تعمل في الخلفية.

## التنفيذ الفعلي

تشرح صفحات التفاصيل الفائدة والبرامج المحتملة ومسار الخطوات ومتطلبات التشغيل: واجهات مدعومة وحسابات وصلاحيات معتمدة، توافق الحقول، شروط الانتقال والمراجعة، سجل دائم ومنع تكرار الأحداث ومراقبة وحدود استخدام وإعادة محاولات. يُحدد ذلك ويُختبر قبل الربط؛ لا يوجد ادعاء بأن أي برنامج يمكن ربطه دون مراجعة إمكاناته.

زر اختيار نموذج يمرر معرّفه في `automation` إلى رسالة التواصل بعد التحقق منه من الكتالوج. اختيارات `design` و`system` السابقة مستمرة. الصفحات الرئيسية والتفاصيل ضمن خريطة الموقع للعربية والإنجليزية فقط؛ المحاكيات `noindex, nofollow` وخارج الخريطة. لا تغييرات في البيانات أو قواعد التشغيل المنشورة ولا استعادة للخدمات التي طلب المالك إلغاءها.

## الملفات والصور والأداء

- الكتالوج: `apps/web/src/content/automation-cases.ts`.
- محرك المحاكاة: `apps/web/src/lib/automation-demo.ts`.
- الواجهة: `apps/web/src/components/automation-preview.tsx` و`automation-demos.css`.
- صور المعرض لقطات فعلية من الواجهات بالعربية والإنجليزية، مخزنة محليًا في `public/brand/automation-demos/` بصيغة WebP مضغوطة وتُخدم مباشرة دون إعادة معالجة على الخادم.
- الحركة تبدأ عند تشغيل الزائر فقط، وتتوقف عند تفضيل تقليل الحركة. لا مفاتيح API أو بيانات اعتماد مطلوبة في المعاينة.

## التحقق ونقطة الرجوع

- نجح بناء الموقع وفحص ESLint وتنسيق الملفات.
- نجحت الاختبارات العامة الـ209، ومنها عشرة اختبارات لمحرك المحاكاة: الشروط، المدخلات، الموافقات، منع التكرار والتعارض، إعادة المحاولة دون نتائج جزئية، وتجميع الملخص.
- نجحت اختبارات المتصفح الـ32 للمعارض الثلاثة والهيدر والصور، تحت حد heap للواجهة قدره 192 ميغابايت. شمل فحص الأتمتة العربية والإنجليزية، مقاسات 1440 و768 و390 و320، الإتاحة والحركة المخفضة، التواصل وصفحات 404 وعدم فهرسة المحاكيات، وغياب طلبات POST في التجربة.
- فُحصت الواجهات والمعرض بصريًا وحُمّلت صور النماذج الستة بنجاح؛ الصور الجديدة تُخدم مباشرة كما هو متبع في تحسين الأداء السابق.
- نقطة الرجوع: `checkpoint/pre-automation-gallery-20261026` عند `0bcf3da`. النشر الفعلي عبر Render خطوة مستقلة.
