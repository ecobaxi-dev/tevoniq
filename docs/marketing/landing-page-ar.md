# صفحة حملات TEVONIQ

المسارات بعد نشر Web وAPI والحزمة المشتركة validation: `/ar/start` و`/en/start`. لا توجد نسخة تركية جديدة.

الصفحة تستخدم خدمات المنشآت الأربع المعتمدة ونموذج التواصل الحالي `/api/leads`، وتعرض النجاح والرقم المرجعي بعد قبول الخادم فقط. الطلبات تظهر في نظام العملاء المحتملين الحالي؛ إرسال البريد يعتمد على إعدادات API القائمة. عند تعذر خيارات النموذج تظهر رسالة بديلة وبيانات الاتصال المنشورة بدل نموذج وهمي. لم تُضف شهادات عملاء أو وعود بنتائج أو أسعار غير معتمدة.

## تجهيز الإعلان

أمثلة روابط (استبدل النطاق بنطاق الإنتاج المعتمد):

- `/ar/start?utm_source=facebook&utm_medium=paid_social&utm_campaign=sme-start`
- `/ar/start?utm_source=instagram&utm_medium=paid_social&utm_campaign=sme-start`
- `/ar/start?utm_source=google&utm_medium=cpc&utm_campaign=sme-start`

تُرسل UTM الموجودة في الصفحة مع الطلب إلى نظام العملاء الحالي. يحتفظ النموذج بمصدر الصفحة. الأحداث التحليلية تقبل القيم المحددة في `growth-events.ts` فقط؛ لا تضع بيانات شخصية في روابط الحملات. لا يوجد حفظ جديد لـclick IDs أو attribution بين زيارات متعددة؛ القياس الإعلاني يعتمد على tags المصرّح بها وإعدادات الحساب والمتصفح.

## التفعيل في لوحة إعدادات الموقع

أدخل المعرّفات العامة في إعدادات Analytics القائمة: Google Analytics (GA4)، Google Tag Manager، Meta Pixel، وMicrosoft Clarity عند الحاجة. لا توجد معرّفات تجريبية أو مفاتيح سرية مضمنة في الصفحة. احترام إعدادات الموافقة الحالية مستمر: GA4 وClarity وفق فئة التحليلات، وMeta وفق التسويق، وGTM يتطلب الفئتين لأن الحاوية تستطيع تحميل النوعين.

- GA4: حدث `generate_lead` بعد الاستلام الناجح. يمكن اعتباره Key event وربطه بـGoogle Ads واستيراده كتحويل.
- بديل Google Ads عبر GTM: Custom Event باسم `tevoniq_generate_lead` يشغّل Google Ads Conversion Tracking tag بمعرّف التحويل وConversion Label من حسابك. جهّز Google tag وConversion Linker وضوابط الموافقة داخل الحاوية. اختر مسار تحويل أساسيًا واحدًا لتجنب احتساب الطلب مرتين عند الجمع مع استيراد GA4.
- عند وجود GA4 وGTM معًا، يرسل الموقع حدث GA4 مباشرة وحدثًا مسمّى ببادئة `tevoniq_` إلى الحاوية. لا تضف tag يكرر GA4 نفسه.
- راجع Enhanced Measurement في GA4 وأوقف قياس النماذج التلقائي إذا كان سيكرر أحداث النموذج المخصصة. احتسب `generate_lead` الناجح فقط كتحويل أساسي.
- Meta Pixel: `Lead` بعد الاستلام الناجح، منفصل عن موافقة التحليلات. لا تضف حدث Lead عند الضغط على زر الإرسال أو فتح الصفحة. لا تضف نسخة ثانية من Pixel عبر GTM عند تشغيله مباشرة من إعدادات الموقع.
- أحداث مساندة: `form_start`، `campaign_cta_click` للزر الرئيسي وزر الهاتف الثابت، `contact_click` للبريد والهاتف، و`demo_open` للنماذج. النقر على وسيلة اتصال ليس تحويل طلب ناجح.
- منطقة النموذج موسومة لـClarity بالإخفاء. الأحداث المخصصة لا تتضمن اسم الزائر أو هاتفه أو بريده أو رسالته.

لا يتضمن هذا التغيير Meta Conversions API أو Enhanced Conversions أو server-side GTM؛ تتطلب هذه إعدادات وأسرارًا وموافقة مناسبة مستقلة. ولا يُعد وجود الكود إثباتًا أن الحسابات الخارجية مفعلة.

## فحص ما قبل إطلاق الإعلان

1. نشر Web وAPI بعد بناء الحزم المشتركة والتحقق من عمل API وTurnstile عند تفعيله، ثم إرسال طلب تجريبي ومراجعة وصوله للنظام والإشعارات.
2. مراجعة البريد والهاتف وسياسة الخصوصية المنشورة في إعدادات الموقع.
3. رفض التتبع ثم التحقق من عدم تحميل الأدوات المحجوبة، وقبول الفئات المطلوبة للتحقق عبر Tag Assistant وGA4 DebugView وMeta Test Events.
4. التأكد من أن الطلب الفاشل لا يحتسب Lead وأن الطلب الناجح يحتسب مرة واحدة.
5. التحقق على الهاتف من النموذج وأزرار التواصل ورابط الإعلان الكامل.
